# S7-08: migraciones 08, 09 y 10 aplicadas en Supabase

Fecha: **09/11/2026**. Proyecto `sugsgvrqxtzeaddkvzii`, rama de producción `main`.
Aplicadas desde el editor SQL del panel de Supabase con la cuenta del
propietario del proyecto (Dante Moya).

## Método

- Se usó el editor SQL porque este equipo no tiene configurada la conexión de
  propietario (`ConnectionStrings:Supabase`). Los comandos `--actualizar-*` de la
  API ejecutan los mismos tres archivos, sin cambios, con esa conexión.
- Se ejecutaron en orden: [`08_Rectificacion_Pesajes.sql`](../02_BASE_DATOS/08_Rectificacion_Pesajes.sql),
  [`09_Mantenedores_Bajas.sql`](../02_BASE_DATOS/09_Mantenedores_Bajas.sql) y
  [`10_Costos_Limites.sql`](../02_BASE_DATOS/10_Costos_Limites.sql). Cada uno va en
  una transacción (`BEGIN`/`COMMIT`): si falla, no queda ningún cambio.
- Antes de ejecutar cada script se comparó el texto del editor con el archivo del
  repositorio: igual largo y huella FNV-1a. Solo se quitó la sangría y se dejó un
  espacio al final de cada línea, lo que no cambia el SQL.

| Script | Caracteres | Huella FNV-1a |
| --- | ---: | ---: |
| 08 | 7 808 | 2356615933 |
| 09 | 5 461 | 692752991 |
| 10 | 14 295 | 2451510018 |

- Supabase advirtió «operaciones destructivas» por los `DROP TRIGGER IF EXISTS`
  y `DROP POLICY IF EXISTS`, que recrean los triggers y políticas de los propios
  scripts y no borran datos.
- En `10` advirtió que `TiposCambio` se creaba sin RLS. Se ejecutó el script
  tal cual («Run without RLS») porque el propio script habilita RLS en esa tabla
  dentro de su bloque `DO`. La verificación final confirma que quedó activo.
